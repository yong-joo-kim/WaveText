# WaveText 개발계획서 (하네스 방식)

- 작성일: 2026-10-23
- 상태: 계획 수립(P0) — 사용자 승인 대기

## 1. 배경과 목표

현장 PC에 복사한 수천 개의 녹취 음성 파일 중에서 **음성이 명료한 구간만 잘라내어**, 음성인식 모델 학습용 **Wave 파일과 Text 파일 쌍**을 빠르게 만드는 윈도우 데스크톱 프로그램을 개발한다.

- 음성인식은 사내 **ZIEUM 스트리밍 음성인식 서버**를 사용한다. WaveText는 다른 제품과 분리된 독립 제품이다.
- 현장 PC는 폐쇄망이므로 **설치 없이 압축만 풀어 실행하는 휴대용 배포판**으로 만든다.
- 개발은 기능별 에이전트가 단계별 승인 게이트를 거쳐 자동으로 진행하는 **하네스 방식**으로 한다.

## 2. 확정 사항

| 항목 | 결정 |
|---|---|
| 언어/화면 | 파이썬 3.12 + PySide6 (Qt) |
| 파형 표시 | pyqtgraph |
| 재생 | PySide6 QtMultimedia (QAudioSink) |
| 노이즈 제거 | noisereduce (스펙트럴 게이팅) + numpy/scipy |
| 음성인식 연동 | ZIEUM 스트리밍 웹소켓 프로토콜 (websocket-client) |
| 버전 관리/배포 | 로컬 Git(태그) + 휴대용 zip (`dist/WaveText_portable_vX.Y.Z.zip`) |
| 참고 화면 폴더 | `docs/reference/ui-screens/` (생성 완료) |

### 음성인식 서버 연동
- 접속: `ws://{host}:{port}/v1/streaming?model={model}`, 인증 헤더 `X-API-Key`
- 절차: `ready` 명령(8000Hz, pcm16, EPD 설정) 전송 → PCM 640바이트 단위 전송 → `finalize` → `finished` 수신 시 종료
- 원본 인식은 단어별 시간(`word_alignment`)을 함께 받아 선택 구간 문장 가져오기에 쓴다.
- 설정: [설정] → [음성인식 서버 설정]에서 서버 주소·포트·접속 방식·API 키·모델을 입력해 `config.local.json`에 저장한다. API 키는 화면·로그에 마스킹한다.
- 제약: 서버는 **8kHz, 16비트, 모노**만 받으므로, 다른 형식의 파일은 인식 요청 전에 변환한다.

## 3. 기능 범위 (꼭 필요한 기능만)

### 화면 구성 (4분할 + 하단 상태줄)

```
┌──────────────────────────────┬──────────────────────────────┐
│ ① 원본 파형                  │ ② 원본 인식 결과 (편집·저장) │
│  재생/정지, 구간 재생,       │  [음성인식 실행] [저장]      │
│  시작/끝 마크, 확대/축소     │                              │
├──────────────────────────────┼──────────────────────────────┤
│ ③ 생성된 학습용 파형         │ ④ 생성된 학습용 텍스트       │
│  재생                        │  (편집·저장)                 │
├──────────────────────────────┴──────────────────────────────┤
│ 파일 목록(폴더 선택) · 이전/다음 · [학습용 파일 생성하기]   │
│ 상태줄: 18.212초 · Wave PCM signed 16bit · 8000Hz · 128kbps · mono │
└─────────────────────────────────────────────────────────────┘
```

### 기능 목록 (요구분석 단계에서 FR 번호 부여)
1. **폴더 선택**: 메뉴/버튼으로 원본 음성 폴더(필수)와 저장 폴더를 지정한다. 파일 목록에 처리 완료 여부를 표시한다.
2. **원본 파형 표시**: 확대/축소와 스크롤, 현재 재생 위치를 표시한다.
3. **재생**: 전체 재생, 정지, 마크 구간만 재생(스피커/이어폰).
4. **구간 마크**: 마우스 드래그나 단축키(`[` 시작, `]` 끝)로 지정하고, 마크 경계를 끌어서 미세 조정한다.
5. **음성인식 실행**: 원본 전체를 서버로 보내 ②에 결과를 표시한다. 진행률을 보여주고 중지할 수 있다.
6. **학습용 파일 생성하기**:
   - 마크 구간을 잘라내고, 노이즈 제거와 경계 클릭음 방지(10ms 페이드)를 적용해 원본과 같은 형식으로 저장한다.
   - 잘라낸 파일을 즉시 음성인식해 ④에 표시하고, ③에 파형을 표시한다.
   - 파일 이름: `원본이름.part-N.wav` / `원본이름.stt-N.txt` (구간은 최대 30초, 같은 원본에서 만들 때마다 번호 증가). 원본 전체 인식 결과는 `원본이름.stt.txt`
   - 저장 폴더: 원본 음성 폴더는 필수다. 원본 음성인식 Text 폴더, 분할 Wav 폴더, 분할 음성인식 Text 폴더를 각각 지정하며, 비워 둔 항목은 원본 음성 폴더 아래 `full-stt\`, `part-wav\`, `part-stt\`에 저장한다.
7. **텍스트 편집·저장**: ②와 ④ 모두 편집 가능하다. ④를 저장하면 학습용 txt를 덮어쓴다(UTF-8).
8. **상태줄**: 길이(초), 인코딩, 비트 수, 샘플레이트, 비트레이트, 채널을 표시한다.
9. **설정**: 음성인식 서버(주소·포트·접속 방식·API 키·모델), 노이즈 제거 강도(약/중/강), 원본 음성 폴더(필수), 원본 음성인식 Text 폴더, 분할 Wav 폴더, 분할 음성인식 Text 폴더.

### 제외 범위
스펙트로그램, 다중 트랙, 이퀄라이저 등 이펙트, 텍스트 외 실행 취소 기록, 일괄 자동 분할.

## 4. 하네스 구성

### 4.1 기능별 에이전트 (`.claude/agents/*.md`)

| 에이전트 | 담당 | 주요 산출물 |
|---|---|---|
| `pm` (총괄) | 단계 진행, 게이트 판정 요청, 상태 갱신, 위험 관리 | `harness/state.json`, `docs/01_pm/진행현황.md` |
| `requirements` (요구분석) | 요구사항 정의, 참고 화면 분석, FR/NFR 번호 부여, 추적표 | `docs/02_requirements/requirements.md` |
| `ui-designer` (UI 시안) | 화면 시안(HTML), 화면 흐름, 단축키 정의 | `docs/03_design/ui/mockup.html`, `design.md` |
| `developer` (구현) | 모듈 구현, 단위 테스트 함께 작성 | `src/wavetext/` |
| `verifier` (검증) | 코드 리뷰, 요구사항 추적 검증, 결함 목록 | `docs/04_test/검증보고서.md` |
| `test-automation` (자동시험) | pytest + pytest-qt 시험 작성·실행, 가짜 음성인식 서버 | `tests/`, `docs/04_test/시험결과.md` |
| `version-control` (버전관리) | 커밋, 태그, 변경 이력 | `CHANGELOG.md`, Git 태그 |
| `release` (배포) | 휴대용 zip 빌드, 사용설명서 | `dist/`, `docs/05_release/`, `docs/06_manual/` |

### 4.2 단계와 승인 게이트

| 단계 | 담당 | 완료 기준 | 게이트 |
|---|---|---|---|
| P0 착수 | pm | 계획서, 하네스 골격(에이전트, state.json, CLAUDE.md), `git init` | **사용자 승인** |
| P1 요구분석 | requirements | FR/NFR 정의, 참고 화면 반영, 미결 사항 정리 | **사용자 승인** |
| P2 UI 시안 | ui-designer | 4분할 시안 HTML, 단축키, 화면 흐름 | **사용자 승인** |
| P3 구현 | developer | 전 기능 구현, 단위 테스트 통과 | 자동 |
| P4 검증 | verifier | 리뷰 결함 0건(치명/주요), 요구사항 추적 100% | 자동 (실패 시 P3로 되돌림) |
| P5 자동시험 | test-automation | 전체 시험 통과, 핵심 모듈 커버리지 80% 이상, 실서버 연동 1회 확인 | 자동 (실패 시 P3로 되돌림) |
| P6 버전관리 | version-control | 커밋 정리, `v0.1.0` 태그, CHANGELOG | 자동 |
| P7 배포 | release | 휴대용 zip, 클린 PC 실행 확인, 사용설명서 | **사용자 승인** |

- P3~P5 되돌림은 최대 3회까지 허용하고, 넘으면 pm이 사용자에게 보고하고 멈춘다.
- `harness/state.json` 형식: `{"phase", "gates", "loop", "note", "artifacts"}`.
- 메인 세션이 pm 역할로 각 에이전트를 순서대로 호출한다. 에이전트끼리는 문서 산출물로만 정보를 넘긴다.

## 6. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 노이즈 제거가 음성을 손상해 학습 품질 저하 | 강도 3단계, 마크 구간 밖 무음부로 노이즈 특성 추정, 처리 전후 비교 재생 |
| 서버 형식 제약(8kHz) | 인식 요청 시에만 변환하고 저장 파일은 원본 형식 유지 |
| 수천 개 파일에서 느린 목록 로딩 | 목록은 헤더만 읽고, 파형은 선택 시 로딩 |
| PySide6 배포 용량(약 150MB) | PyInstaller 폴더 방식 + 미사용 Qt 모듈 제외 |
| 실서버가 없는 개발 환경 | 가짜 음성인식 서버로 자동시험, 실서버 시험은 별도 표시 |

## 7. 검증 방법
- 단위: 잘라내기 샘플 정확도, 페이드, 노이즈 제거 후 SNR 개선, wav 속성 문자열, 결과 병합
- 화면(pytest-qt): 마크 → 생성 → ③④ 표시, 텍스트 저장, 상태줄 표시
- 연동: 가짜 웹소켓 서버로 `ready`→음성 전송→`finalize`→`finished` 절차 검증, 실서버 1회 확인
- 배포: 압축을 푼 새 폴더에서 `WaveText.exe` 실행 → 샘플 파일 1건 처리
- 실행 명령: `python -m wavetext`, `pytest`, `pytest tests/unit/test_segment.py::이름`, `python tools/build_portable.py`
